# Сквозная проверка (пункт 5.4)

Набор проверок по разделу 15 ТЗ и разделу 14 ТЗ v4. Каждая проверка подписана
кодом критерия, поэтому отчёт читается прямо против списка приёмки, а не против
имён функций.

## Как запускать

```bash
npm run build          # проверки идут по out/, так что сборка должна быть свежей
npm test               # все наборы, кроме админки, в Chromium
npm test -- --browser all                  # Chrome, Firefox, Safari (WebKit), Edge — Т-02
npm test -- --site https://nazarov.net     # по боевому сайту
npm test -- --suite public,trip            # только выбранные наборы
npm test -- --headed                       # с видимым окном, чтобы посмотреть глазами

# админка: нужны настоящие логин и пароль, в файлах их нет
YACHT_LOGIN=… YACHT_PASSWORD=… npm test -- --suite admin

npm run lighthouse -- --runs 5             # Т-01: медиана пяти прогонов
npm run lighthouse -- --psi                # Т-01: меряет Google, не эта машина
```

Код выхода — число непрошедших проверок, так что запуск годится и для CI.

Без `--site` набор сам поднимает `out/` на свободном порту и ходит по нему: это
ровно то, что уехало бы в деплой. С `--site` те же файлы проверяют живой сайт.

## Наборы

| Набор | О чём | Критерии |
| --- | --- | --- |
| `public` | меню, главная, направления, два языка, ширины от 320 px, политика, карта сайта, 404 | П-01…П-16, С-01…С-05, С-14, С-16, С-17, Т-05, Т-06 |
| `trip` | страница поездки, кнопки «Поделиться», превью для соцсетей | Ш-01…Ш-05, С-06, С-15, П-06, П-09 |
| `forms` | подписка, заявка, идея, Solutions, отписка | Н-01…Н-12, С-05…С-07, П-14, Т-05 |
| `platform` | каждая страница в каждом движке, карта сайта, robots, http→https | Т-02, Т-03, Т-06, П-15 |
| `admin` | вход, поездка целиком, дни, предпросмотр, архив, копия, удаление, подписчики, заявки, панель с телефона | А-01…А-18, С-07, С-08, С-13, С-16, П-04, П-06 |

`platform` — единственный набор, который прогоняется во всех движках: остальные
в каждом браузере дали бы один и тот же ответ вчетверо дольше.

## Три решения, которые стоит знать

**Turnstile подменяется.** Cloudflare Turnstile отказывает автоматизированному
браузеру — так и задумано, и уговорить его нельзя. Без подмены формы навсегда
застревают на «проверяем, что вы человек», и за ними ничего не проверить.
Проверяется форма, а не Cloudflare: настоящий виджет проходит человек, а
серверная половина — то, что запрос без токена отклоняется, — живёт в воркере.

**Формы никуда не отправляются.** Каждая точка `/api/…` отвечает прямо в
браузере. Так проверяются две вещи, которых не видно по настоящей отправке: что
именно страница посылает (где и обнаруживается лишнее или потерянное поле) и
что она показывает в ответ. И боевая база остаётся нетронутой.

**Админка пишет в настоящую базу — и убирает за собой.** Всё, что она создаёт,
это **черновик**: посетителю он не виден и пересборку не запускает (`rebuildAfterTrip`
запускает её только для поездки, которая опубликована или была опубликована).
Набор удаляет созданное и честно пишет в отчёт, если удалить не удалось. Он
никогда не публикует, не рассылает, не трогает чужие поездки и не удаляет
подписчиков.

| А-05 | загрузка фото с камеры и из галереи — нужен настоящий телефон |

## Lighthouse (Т-01)

`npm run lighthouse` гоняет мобильный профиль по главной, разделу и странице
поездки и сверяет с порогами ТЗ: 85 за производительность, 90 за доступность и
SEO. Отчёты — в `lighthouse/` (каталог в `.gitignore`).

**Локальному прогону нужна незанятая машина.** Lighthouse замедляет процессор,
на котором меряет, в фиксированное число раз — поэтому всё, чем машина занята
ещё, ложится прямо в результат. Три прогона одной и той же страницы дали здесь
98, 86 и 79 при одинаковых сетевых таймингах: картинка каждый раз приходила за
150 мс, а отрисовка ждала основной поток то 115 мс, то 2013. Это про ноутбук, а
не про сайт.

Поэтому:

```bash
npm run lighthouse -- --runs 5    # медиана пяти прогонов
npm run lighthouse -- --psi       # считает Google, а не эта машина
```

`--psi` спрашивает PageSpeed Insights — тот же Lighthouse на серверах Google,
и его число ни от чего здесь не зависит. Без ключа квота общая на всю сеть и
быстро кончается: бесплатный ключ из консоли Google Cloud передаётся в
`PSI_KEY`. Это и есть число для отчёта; то же самое показывает
[pagespeed.web.dev](https://pagespeed.web.dev) в браузере.

По умолчанию меряется **боевой сайт**. Локальная сборка, которую отдаёт
маленький node-сервер по http, идёт без сжатия, без заголовков кэша и без CDN —
её числа ничего не говорят о том, что получает посетитель. `--local` нужен,
чтобы сравнить две сборки между собой, а не для критерия.

Сам Lighthouse берётся установленным или через `npx` и не записан в
зависимости: он тянет за собой несколько сотен пакетов ради того, что
запускается несколько раз в год, а зависимость в `package.json` деплой ставит
при каждой сборке.

## Картинки (тоже Т-01)

`node scripts/image-variants.mjs` делает WebP-копии фотографий из
`public/assets` в 480, 960 и 1440 пикселей и пишет манифест, из которого
компонент `<Photo>` собирает `srcset`. Сайт — статическая выгрузка, и файл из
репозитория телефон скачивает как есть: фотография шириной 1920 в рамке
шириной 480 — это вчетверо больше байтов без разницы на глаз. Добавили
фотографию в `public/assets` — запустите скрипт и закоммитьте, что появилось;
`--check` скажет, не забыл ли кто.

## Если проверка не прошла

Отчёт печатает строку вида

```
chromium/public · П-15 · 320 px · /sailing/ — вылезает на 24 px
```

— набор, критерий, что проверялось и что получилось. Смотреть глазами:
`npm test -- --suite public --headed`.
