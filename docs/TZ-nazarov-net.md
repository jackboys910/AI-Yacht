## 1. Коротко о задаче

Сейчас nazarov.net — одностраничный лендинг одной поездки (AI Yacht, 12–22 ноября 2026) на русском и английском, плюс страница IT Solutions.

Нужно превратить его в личный сайт владельца с разделами-направлениями **«Яхтинг»** (англ. Sailing) и **«Сноубординг»** (англ. Snowboarding):

- в каждом разделе — поездки, которые владелец сам создаёт, публикует и убирает в архив через простую админку;
- страница каждой поездки выглядит как нынешний лендинг AI Yacht (по образцу aiyacht.top): первый экран, цена, программа, маршрут по дням, фото, команда, вопросы, заявка;
- посетитель может одной кнопкой подписаться на новости направления — только email;
- поездкой можно поделиться в Facebook и мессенджерах, и ссылка выглядит красиво: картинка, название, даты;
- отдельная страница «Обо мне» — с YouTube-каналом владельца.

Всё содержимое сайта ведётся на двух языках: русском и английском.

Это не платформа и не сервис для сторонних пользователей. Это сайт одного человека: сейчас у него два направления, новые (например, скайдайвинг) владелец добавит сам.

## 3. Цели

1. Владелец сам, без разработчика, публикует поездки по направлениям: тексты, фото, маршрут по дням — на русском и английском.
2. Одновременно могут висеть несколько поездок (например, ноябрь и май), прошедшие убираются в архив.
3. Сайт собирает подписчиков по каждому направлению — только email — и сообщает им о новых поездках.
4. Люди из рекламы и постов в Facebook попадают сразу на страницу конкретной поездки и видят кнопку подписки.
5. Через YouTube-канал люди знакомятся с владельцем и его путешествиями.

## 7. Админка

### 7.1. Как выглядит работа владельца

1. Войти в админку с компьютера или телефона.
2. Нажать «Новая поездка» или «Дублировать» прошлую, чтобы не заполнять всё с нуля.
3. Заполнить блоки на русском и английском, загрузить фото, расписать дни маршрута.
4. Сохранить как черновик, дописать позже.
5. Посмотреть предпросмотр — так, как увидят посетители.
6. Нажать «Опубликовать».
7. Нажать «Разослать подписчикам» — письмо уйдёт всем подписчикам направления.
8. Поделиться ссылкой в Facebook.
9. После поездки — «В архив».

### 7.2. Поездки

- Список поездок с фильтром по направлению и статусу: черновик, опубликовано, архив.
- Создание и редактирование всех блоков из п. 6.3 через обычные поля формы — без знания программирования.
- У каждого текстового поля две вкладки: RU и EN. Опубликовать поездку можно, только когда обязательные блоки заполнены на обоих языках; чего не хватает — админка подсказывает.
- Маршрут по дням: добавить день, удалить, поменять местами.
- Загрузка фото с компьютера и с телефона (галерея или камера). Фото автоматически уменьшаются и сжимаются.
- Черновик, предпросмотр, публикация, снятие с публикации (архив), возврат из архива, галочка «Показывать в прошедших».
- «Дублировать»: копия поездки со всеми блоками сохраняется как черновик.
- Удаление — только с подтверждением.
- Адрес страницы (например, /sailing/grenadines-nov-2026) создаётся из названия автоматически, при желании его можно поменять.
- Поля для соцсетей (картинка, заголовок, описание) заполняются автоматически, при желании их можно поменять.

### 7.3. Направления

- Список направлений: название и описание (RU и EN), обложка, адрес, порядок в меню, плейлист YouTube.
- Добавить новое направление (например, «Скайдайвинг») может сам владелец — раздел появится в меню и на главной без участия разработчика.
- Направление можно скрыть, не удаляя поездки.

### 7.4. Люди (команда)

- Справочник людей: фото, имя, роль и описание на двух языках.
- В поездку люди добавляются выбором из справочника — не нужно вводить заново для каждой поездки.

### 7.5. Подписчики

- Список подписчиков: email, направления, дата подписки, откуда пришёл (например, из рекламы Facebook).
- Количество подписчиков по каждому направлению.
- Выгрузка в CSV (открывается в Excel и Google Таблицах).
- Удаление подписчика по его просьбе.

### 7.6. Заявки

- Список заявок: поездка, имя, контакт, комментарий, дата.
- Фильтр по поездке, отметка «обработано».
- Каждая новая заявка дублируется письмом на support@ctmass.com.

### 7.7. Настройки и «Обо мне»

- Текст и фото «Обо мне» на двух языках, ссылка на YouTube-канал, ссылки на соцсети.
- Почтовый адрес отправителя для писем — требование закона США CAN-SPAM (см. п. 8.2).

### 7.8. Мобильная версия

Админкой удобно пользоваться с телефона: создать поездку с фото, опубликовать и разослать можно, не подходя к компьютеру.

### 7.9. Доступ

- Вход по логину и паролю. Без входа админка недоступна.
- Пользователь один — владелец. Если зайти нужно кому-то ещё, он делает это под аккаунтом владельца.

## 8. Подписка и уведомления

### 8.1. Как подписывается посетитель

1. Нажимает «+ Подписаться» на любой странице.
2. Вводит только email — телефон не нужен.
3. Направление текущей страницы уже отмечено; можно отметить и другие.
4. Отмечает согласие на получение писем со ссылкой на политику конфиденциальности.
5. Видит сообщение: «Вы подписались на новости по направлению Яхтинг».
6. Подписка активна сразу, подтверждать её по письму не нужно.
7. Получает приветственное письмо: какие направления выбраны и как отписаться.

### 8.2. Письма подписчикам

| Письмо | Когда уходит | Что внутри |
| --- | --- | --- |
| Приветствие | Сразу после подписки | Выбранные направления, ссылка управления подпиской |
| Анонс новой поездки | Когда владелец нажимает «Разослать подписчикам» | Обложка, название, даты, место, кнопка «Подробнее» |

- Анонс получают только подписчики направления этой поездки, на их языке.
- Перед отправкой владелец видит предпросмотр письма и число получателей.
- Один анонс уходит один раз: повторная отправка той же поездки требует отдельного подтверждения.
- Письма уходят с support@ctmass.com через EmailJS — сервис, который уже оплачен и настроен.
- По закону США CAN-SPAM (аудитория из США) в каждом письме обязательны ссылка отписки и почтовый адрес отправителя. Адрес заказчик указывает один раз в настройках.

**Известное ограничение — лимит EmailJS.** Оплачен тариф Personal: **2 000 отправок в месяц**, и этот лимит общий с сайтом ctmass.com, который пользуется тем же аккаунтом.

Каждое письмо одному подписчику — одна отправка. Считать нужно так:

| Что уходит | Сколько отправок |
| --- | --- |
| Анонс поездки | По одной на каждого подписчика направления |
| Приветственное письмо | Одна на каждую новую подписку |
| Письмо о заявке | Одна на каждую заявку |
| Письма сайта ctmass.com | Из того же лимита |

При 200 подписчиках и двух анонсах в месяц уходит около 400 отправок — запас большой. Потолок наступает примерно на 500–700 подписчиках при двух рассылках в месяц: тогда лимит в 2 000 будет выбираться целиком.

Что делаем при приближении к лимиту: либо переходим на более дорогой тариф EmailJS, либо переводим рассылку на почтовый сервис (у них есть бесплатные тарифы) — это отдельная работа, ориентир 8–10 часов. Приветственные письма и письма о заявках в любом случае остаются на EmailJS.

Перед отправкой админка показывает число получателей, чтобы владелец видел, сколько отправок спишется. Остаток лимита виден в личном кабинете EmailJS.

### 8.3. Отписка

- В каждом письме есть ссылка «Отписаться».
- Отписка работает в один-два клика, без пароля.
- На той же странице можно не отписываться полностью, а убрать отдельные направления.
- После отписки письма не приходят.

## 9. Заявки на участие

- Форма на странице каждой поездки: имя, контакт (телефон / Telegram / WhatsApp), email (необязательно), комментарий.

- После отправки посетитель видит подтверждение, как сейчас.
- Подписка и заявка — разные вещи: подписка значит «держите в курсе», заявка — «хочу поехать в эту поездку».

## 10. «Поделиться» и соцсети

- На странице поездки кнопки: Facebook, WhatsApp, Telegram, «Скопировать ссылку». На телефоне — системное меню «Поделиться», через него можно отправить ссылку в том числе в Instagram.
- Ссылка ведёт на страницу конкретной поездки, а не на главную.
- При публикации ссылки в Facebook, Telegram и WhatsApp появляется красивое превью: картинка, название, даты. Картинка для соцсетей собирается автоматически из обложки, названия и дат поездки.
- Свои данные для превью есть у каждой страницы: главной, разделов, «Обо мне».
- В ссылках «Поделиться» проставляются метки источника, чтобы в статистике было видно, откуда пришёл человек.

Ограничение Instagram: он не принимает ссылки в обычных постах — только в сторис, в описании профиля и в личных сообщениях. Это ограничение самого Instagram, не сайта.

**Скорость.** Страницы открываются быстро на мобильном интернете: фото сжимаются автоматически, подгружаются по мере прокрутки.

**Браузеры.** Последние версии Chrome, Safari (iPhone и Mac), Firefox, Edge.

**Языки.** Интерфейс и всё содержимое — на русском и английском.

**Безопасность.** HTTPS на всех страницах. Админка закрыта паролем. Формы защищены от спам-ботов невидимой проверкой Cloudflare Turnstile — посетителю не нужно решать капчу.

**Резервные копии.** Данные сайта выгружаются по расписанию; восстановление проверяется до сдачи.

**Поисковики.** Карта сайта для Google, правильные заголовки страниц, разметка языковых версий. Архивные поездки из карты сайта исключаются.

**Реклама и аналитика.** Пиксель Facebook на всех страницах и события «Подписка» и «Заявка», в том числе через серверную отправку (Conversions API) — чтобы реклама считала конверсии точнее. Запускается только после согласия в баннере cookies.

**Персональные данные.** Политика конфиденциальности на двух языках, согласие в формах, отписка и почтовый адрес отправителя в каждом письме (CAN-SPAM, аудитория США).

**Доступы.** Все аккаунты сервисов оформлены на заказчика. Исполнитель передаёт полный список доступов.

### 11.1. Пиксель Facebook и серверные события — зачем они нужны

**Пиксель** — невидимый счётчик на страницах сайта. Он сообщает Facebook, что человек пришёл по рекламе и что он дальше сделал: посмотрел поездку, подписался, оставил заявку. Без него реклама показывает только клики, а сколько из них превратились в подписчиков — неизвестно.

Что это даёт:

- видно стоимость одной подписки и одной заявки, а не просто цену клика;
- алгоритм Facebook учится показывать рекламу тем, кто действительно подписывается, а не тем, кто просто кликает — цена подписчика снижается;
- можно догнать рекламой тех, кто открыл поездку, но не подписался;
- можно попросить Facebook найти людей, похожих на уже подписавшихся.

**Серверные события (Conversions API)** — это те же события, но отправленные с сайта напрямую в Facebook, а не из браузера. Браузерные события теряются: их режут блокировщики рекламы и ограничения Apple на iPhone. Часть подписок из-за этого не доходит до статистики, и реклама «не понимает», что сработала. Серверный канал закрывает эту дыру. Оба канала работают вместе, повторы Facebook отсеивает сам.

Пиксель и токен для серверных событий создаёт исполнитель в рекламном кабинете заказчика — для этого нужен доступ к Facebook Business. Работа входит в пункт 18 сметы.

## Приложение А. Техническое решение

Раздел для исполнителя. Финальные детали подтверждаются на этапе 0 техническим прототипом.

**Главное изменение.** Сейчас сайт статический: страницы собираются заранее, базы нет. Появляются база данных, хранилище фото и админка. Дизайн и компоненты текущего сайта переиспользуются: страница поездки — это нынешний лендинг AI Yacht, который собирается из данных админки.

| Часть | Решение | Примечание |
| --- | --- | --- |
| Сайт | Текущий проект на Next.js, статическая сборка на Cloudflare | Бесплатно, быстрые страницы, хорошая индексация |
| Обновление сайта | Публикация в админке запускает пересборку и выкладку | Изменения появляются за 2–5 минут, отсюда критерии А-08 и А-09 |
| База данных | Firebase Firestore | Бесплатного тарифа хватает с запасом при нашем объёме |
| Фото | Firebase Storage, сжатие перед загрузкой | Для новых проектов может потребоваться тариф Blaze с картой |
| Админка | Своя, внутри сайта, на Firebase Auth | Готовые CMS (например, Payload) требуют отдельного сервера и платного хостинга — под этот проект дороже и сложнее |
| Письма | EmailJS с support@ctmass.com | Массовая рассылка — с ограничениями, см. п. 8.2 |
| Защита форм | Cloudflare Turnstile | Бесплатно |
| Реклама | Пиксель Facebook и серверная отправка событий | Запускается после согласия в баннере cookies |
| YouTube | Ленты канала и плейлистов | Не нужен ключ API, обновление раз в час |

**Основные данные:**

| Сущность | Поля |
| --- | --- |
| Направление | Название и описание RU/EN, адрес, обложка, порядок, плейлист YouTube, видимость |
| Поездка | Направление, даты, место, обложка, статус набора, статус публикации, «показывать в прошедших», цена, места, все блоки из п. 6.3 на двух языках, поля для соцсетей, отметка «анонс отправлен» |
| Человек | Имя, роль и описание RU/EN, фото |
| Подписчик | Email, направления, язык, дата, источник перехода, признак отписки |
| Заявка | Поездка, имя, контакт, email, комментарий, дата, отметка «обработано» |
| Настройки | «Обо мне» RU/EN, YouTube-канал, соцсети, почтовый адрес для писем |
