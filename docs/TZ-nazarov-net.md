## 1. Коротко о задаче

Сейчас nazarov.net — одностраничный лендинг одной поездки (AI Yacht, 12–22 ноября 2026) на русском и английском, плюс страница IT Solutions.

Нужно превратить его в личный сайт владельца с разделами-направлениями **«Сейлинг»** и **«Сноубординг»**:

- в каждом разделе — поездки, которые владелец сам создаёт, публикует и убирает в архив через простую админку;
- страница каждой поездки выглядит как нынешний лендинг AI Yacht (по образцу aiyacht.top): первый экран, цена, программа, маршрут по дням, фото, команда, вопросы, заявка;
- посетитель может одной кнопкой подписаться на новости направления — только email;
- поездкой можно поделиться в Facebook и мессенджерах, и ссылка выглядит красиво: картинка, название, даты;
- отдельная страница «Обо мне» — с YouTube-каналом владельца.

Это не платформа и не сервис для сторонних пользователей. Это сайт одного человека: сейчас у него два направления, новые (например, скайдайвинг) можно будет добавить позже.

## 3. Цели

1. Владелец сам, без разработчика, публикует поездки по направлениям: тексты, фото, маршрут по дням.
2. Одновременно могут висеть несколько поездок (например, ноябрь и май), прошедшие убираются в архив.
3. Сайт собирает подписчиков по каждому направлению — только email — и сообщает им о новых поездках.
4. Люди из рекламы и постов в Facebook попадают сразу на страницу конкретной поездки и видят кнопку подписки.
5. Через YouTube-канал люди знакомятся с владельцем и его путешествиями.

- Последние видео с YouTube-канала.
- Блок подписки.

### 6.2. Раздел направления

- Обложка и короткое описание направления — заполняются в админке.

## 7. Админка

### 7.1. Как выглядит работа владельца

1. Войти в админку с компьютера или телефона.
2. Нажать «Новая поездка» или «Дублировать» прошлую, чтобы не заполнять всё с нуля.
3. Заполнить блоки, загрузить фото, расписать дни маршрута.
4. Сохранить как черновик, дописать позже.
5. Посмотреть предпросмотр — так, как увидят посетители.
6. Нажать «Опубликовать».
7. Нажать «Разослать подписчикам» — письмо уйдёт всем подписчикам направления.
8. Поделиться ссылкой в Facebook.
9. После поездки — «В архив».

### 7.2. Поездки

- Список поездок с фильтром по направлению и статусу: черновик, опубликовано, архив.
- Создание и редактирование всех блоков из п. 6.3 через обычные поля формы — без знания программирования.
- Маршрут по дням: добавить день, удалить, поменять местами.
- Загрузка фото с компьютера и с телефона (галерея или камера). Фото автоматически уменьшаются и сжимаются.
- Черновик, предпросмотр, публикация, снятие с публикации (архив), возврат из архива.
- «Дублировать»: копия поездки со всеми блоками сохраняется как черновик.
- Удаление — только с подтверждением.
- Адрес страницы (например, /sailing/grenadines-nov-2026) создаётся из названия автоматически, при желании его можно поменять.
- Поля для соцсетей (картинка, заголовок, описание) заполняются автоматически, при желании их можно поменять.

### 7.3. Направления

- Список направлений: название (RU/EN), обложка, описание, порядок в меню, плейлист YouTube.
- Добавить новое направление (например, «Скайдайвинг») может сам владелец — раздел появится в меню и на главной без участия разработчика.
- Направление можно скрыть, не удаляя поездки.

### 7.4. Люди (команда)

- Справочник людей: фото, имя, роль, описание.
- В поездку люди добавляются выбором из справочника — не нужно вводить заново для каждой поездки.

### 7.5. Подписчики

- Список подписчиков: email, направления, дата подписки, откуда пришёл (например, из рекламы Facebook).
- Количество подписчиков по каждому направлению.
- Выгрузка в CSV (открывается в Excel и Google Таблицах).
- Удаление подписчика по его просьбе.

### 7.6. Заявки

- Список заявок: поездка, имя, контакт, комментарий, дата.
- Фильтр по поездке, отметка «обработано».
- Каждая новая заявка дублируется письмом владельцу.

### 7.7. Настройки и «Обо мне»

- Текст и фото «Обо мне», ссылка на YouTube-канал, ссылки на соцсети.
- Email, на который приходят уведомления о заявках.

### 7.8. Мобильная версия

Админкой удобно пользоваться с телефона: создать поездку с фото, опубликовать и разослать можно, не подходя к компьютеру.

### 7.9. Доступ

- Вход по логину и паролю. Без входа админка недоступна.
- Количество пользователей и их права — вопрос 13.

## 8. Подписка и уведомления

### 8.1. Как подписывается посетитель

1. Нажимает «+ Подписаться» на любой странице.
2. Вводит только email — телефон не нужен.
3. Направление текущей страницы уже отмечено; можно отметить и другие.
4. Отмечает согласие на получение писем со ссылкой на политику конфиденциальности.
5. Видит сообщение: «Вы подписались на новости по направлению Сейлинг».
6. Получает письмо: приветствие или подтверждение подписки — зависит от ответа на вопрос 5.

### 8.2. Письма подписчикам

| Письмо | Когда уходит | Что внутри |
| --- | --- | --- |
| Подтверждение / приветствие | Сразу после подписки | Какие направления выбраны, ссылка управления подпиской |
| Анонс новой поездки | Когда владелец нажимает «Разослать подписчикам» | Обложка, название, даты, место, кнопка «Подробнее» |

- Анонс получают только подписчики направления этой поездки.
- Перед отправкой владелец видит предпросмотр письма и число получателей.
- Один анонс уходит один раз: повторная отправка той же поездки требует отдельного подтверждения.
- Письма уходят с адреса на домене nazarov.net (вопрос 14) и настраиваются так, чтобы не попадать в спам.

### 8.3. Отписка

- В каждом письме есть ссылка «Отписаться».
- Отписка работает в один-два клика, без пароля.
- На той же странице можно не отписываться полностью, а убрать отдельные направления.
- После отписки письма не приходят.

## 9. Заявки на участие

- Форма на странице каждой поездки: имя, контакт (телефон / Telegram / WhatsApp), email (необязательно), комментарий.
- Заявка сохраняется в админке и приходит письмом владельцу.
- После отправки посетитель видит подтверждение, как сейчас.
- Подписка и заявка — разные вещи: подписка значит «держите в курсе», заявка — «хочу поехать в эту поездку».

## 10. «Поделиться» и соцсети

- На странице поездки кнопки: Facebook, WhatsApp, Telegram, «Скопировать ссылку». На телефоне — системное меню «Поделиться», через него можно отправить ссылку в том числе в Instagram.
- Ссылка ведёт на страницу конкретной поездки, а не на главную.
- При публикации ссылки в Facebook, Telegram и WhatsApp появляется красивое превью: картинка, название, даты. Картинка для соцсетей собирается автоматически из обложки, названия и дат поездки.
- Свои данные для превью есть у каждой страницы: главной, разделов, «Обо мне».

Ограничение Instagram: он не принимает ссылки в обычных постах — только в сторис, в описании профиля и в личных сообщениях. Это ограничение самого Instagram, не сайта.

## 11. Общие требования

**Дизайн.** Стиль нынешнего nazarov.net и aiyacht.top: те же шрифты, цвета, карточки. Новые страницы собираются из тех же элементов.

**Адаптивность.** Сайт и админка корректно работают на экранах шириной от 320 px (маленький телефон) до широких мониторов, без горизонтальной прокрутки.

**Скорость.** Страницы открываются быстро на мобильном интернете: фото сжимаются автоматически, подгружаются по мере прокрутки.

**Браузеры.** Последние версии Chrome, Safari (iPhone и Mac), Firefox, Edge.

**Языки.** Интерфейс на русском и английском, как сейчас. Нужен ли перевод самих поездок — вопрос 4.

**Безопасность.** HTTPS на всех страницах. Админка закрыта паролем. Формы защищены от спам-ботов невидимой проверкой — посетителю не нужно решать капчу.

**Резервные копии.** База сайта сохраняется автоматически; восстановление из копии проверяется до сдачи.

**Поисковики.** Карта сайта для Google (sitemap), правильные заголовки страниц. Архивные поездки из карты сайта исключаются.

**Аналитика.** Статистика посещений, источников и подписок. Конкретный инструмент — вопрос 11.

**Персональные данные.** Страница политики конфиденциальности, согласие в формах, отписка в каждом письме. Требования зависят от того, откуда аудитория, — вопрос 12.

**Доступы.** Все аккаунты сервисов (хостинг, рассылка и т.д.) регистрируются на заказчика. Исполнитель передаёт полный список доступов.

## 14. Порядок приёмки

2. Заказчик проходит критерии приёмки из раздела 15 и оставляет замечания комментариями в этом документе.

5. Сайт переключается на nazarov.net, исполнитель проверяет боевую версию.
6. Работа считается принятой, когда все критерии отмечены как выполненные.

## Приложение А. Техническое решение

Раздел для исполнителя. Финальный выбор подтверждается на этапе 0 техническим прототипом.

**Что меняется.** Сейчас сайт статический: страницы собираются заранее, базы нет. Для админки, подписчиков и рассылок нужны база данных, хранилище фото и серверная часть. Дизайн и компоненты текущего сайта переиспользуются: страница поездки — это нынешний лендинг AI Yacht, который собирается из данных админки.

| Часть | Решение | Примечание |
| --- | --- | --- |
| Сайт | Текущий проект на Next.js 16, серверный режим на Cloudflare Workers | Хостинг и домен уже настроены |
| Админка | Готовая CMS с редактором, черновиками и загрузкой фото, например Payload CMS | Payload умеет работать на Cloudflare. Альтернатива — облачная CMS Sanity |
| База данных | Cloudflare D1 | Встроенное восстановление на любой момент за последние дни |
| Фото | Cloudflare R2 и автоматическое сжатие | Без платы за трафик |
| Рассылки | Почтовый сервис со списками и отпиской, например Brevo или MailerLite | Двойное подтверждение подписки, отписка и шаблоны писем из коробки; EmailJS для рассылок не подходит |
| YouTube | RSS-ленты канала и плейлистов | Не нужен ключ API; обновление раз в час |
| Защита форм | Cloudflare Turnstile | Невидимая проверка вместо капчи |
| Аналитика | Cloudflare Web Analytics, по решению — Google Analytics и пиксель Facebook | Cloudflare Web Analytics работает без cookies |
| Почта домена | Записи SPF, DKIM и DMARC для nazarov.net | DNS уже в Cloudflare |
